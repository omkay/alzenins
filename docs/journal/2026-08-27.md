## Decisions taken

Four of the ten Phase 0 questions were answered by the owner. All four are recorded as
ADRs or scope changes, not just here.

- **ADR-0003 → Accepted, Option A.** MamoPay only. No Stripe in v1. The eight markets
  MamoPay cannot charge get an explicit fallback charge currency:
  Oman/Kuwait/Bahrain/Jordan → **AED** (dollar-pegged, keeps the number stable),
  Iraq/Palestine → **USD**, Morocco → **EUR**, Japan → **USD**.
  The `PaymentProvider` port is still built, so Option B stays a later adapter.
- **MamoPay sandbox key issued.** Stored in `.env.local` only. Phase 2 is unblocked.
- **[ADR-0007](../decisions/ADR-0007-vat-treatment.md) → UAE VAT 5%, tax-inclusive,
  provisional.** Displayed prices are what the customer pays. `tax_rate` and
  `tax_treatment` are stored **per order** so a later correction is a settings change plus
  a backfill rather than a migration. Still needs the accountant's written determination —
  that is now a Phase 9 sign-off item.
- **Store is digital only.** No physical goods ever. Phase 7 drops shipping zones, carrier
  integration, customs, stock levels, oversell protection, variants, packing slips, returns
  and address collection — it roughly halves, from 2–3 weeks to **1–2 weeks**.

## Learned

- **The digital-only decision invalidates two of the eight design artboards.** The
  published store mockups show a Genki textbook, calligraphy pens, stock counters, a
  shipping quote to Riyadh, a free-shipping threshold and a 14-day physical return. None of
  that exists now. Flagged prominently in `docs/design/screen-priorities.md`; both artboards
  need reworking before Phase 7 design starts. The other six are unaffected.
- Digital-only makes the store almost free architecturally: a purchase grants an
  `entitlement` and downloads are signed URLs behind an entitlement check — the same
  mechanism recorded courses already need. There is no separate "download" system to build.

## Bugs found — four real ones

1. **`trustHost` missing.** Auth.js returns `UntrustedHost` for every route in
   production. Vercel sets it implicitly, nothing else does — so any self-hosted
   or containerised deployment was broken. Found by running E2E against a
   production build rather than `next dev`.
2. **Client-side `signOut()` did not end the session.** It clears the cookie via
   /api/auth/signout, but `SessionProvider`'s own /api/auth/session request can
   land in that window and re-issue the JWT. Now a server action.
3. **`#a96f2d` fails AA as a text colour — and this document told people to use
   it.** `design-system.md` §6 said it was the safe gold for text. Measured:
   3.93:1 on cream, 4.14:1 on card. Both below the 4.5 floor. `--accent-text` is
   now `#7a4f1c` (6.63:1), and the document carries a correction rather than a
   quiet edit.
4. **A decorative gradient bloom broke contrast underneath it.** After darkening
   the token the home-page eyebrow *still* failed at 4.37:1, because the chip's
   translucent background let the hero's blurred bloom through — Lighthouse
   measured the effective background as `#dec8ac`, not cream. Fixed with an
   opaque `--accent-subtle`. **Text contrast must not depend on what happens to
   be painted behind it.**

## Learned

- **`NODE_ENV` is not a usable gate when tests run a production build.** Both
  the E2E code sink and the kitchen-sink route key on `APP_URL` being localhost
  instead. That is now the single most important variable to get right on a
  deployed environment — noted at the top of `deployment.md`.
- **Pixel snapshots are the wrong tool for RTL cover here.** macOS baselines do
  not match Ubuntu CI, so committed screenshots fail every run for reasons
  unrelated to the code. The RTL suite asserts direction, horizontal overflow at
  desktop and phone widths, glyph-level text alignment (measured with a `Range`,
  since a block heading's own box is identical in both directions), and the
  switch knob's travel.
- **`posthog-js` in the main bundle cost real performance.** Moving it to a
  dynamic import inside the effect took TBT from 120ms to 40ms and performance
  from 84 to 93.
- **`hreflang` needs fully-qualified URLs.** Relative hrefs fail the Lighthouse
  audit and are ignored by search engines. Fixed with `metadataBase` plus an
  `x-default` pointing at Arabic.
- CI asserts **accessibility at 100, not 90**. A 90 floor would have hidden the
  contrast bug that started this.
